# ADR-003: Vector 검색 score 0.4 컷오프

**Status**: Accepted
**Date**: 2026-05-07
**Decision makers**: 시원 (DX/AX)

## Context

LLM 콘텐츠 산출물에 ETF와 무관한 어휘가 섞이는 현상이 관찰됨. 추적해보니 RAG의 Vector 검색에서 **무관 블로그가 top-k 안에 들어오는 것**이 원인:

| Query | top-1 결과 (필터 없음) | FAISS score |
|---|---|---|
| "레버리지" | "26년 5월 6일 수요일 간추린 아침뉴스/해당화 축복 힐링 정원" | 0.320 |
| "반도체" | 동일 | 0.321 |
| "연금" | "김 대리, 붉은 금의 비밀..." | 0.359 |

기존 vector_store.search()는 FAISS 점수와 무관하게 top-k를 무조건 반환하고 있었음.

## Investigation

세 가지 가설을 검증:

### H1: 블로그 필터링이 헐거워서 노이즈가 인덱스에 섞여있다
- proxy_score 임계값 0.2, etf_mentions ≥ 1로 필터링됨
- **결과**: 980건 중 노이즈로 의심되는 블로그 6건 확인 (등산일기·언박싱·아침뉴스 류)
- 이들의 proxy_score는 0.61~0.73 — **중상위에 분포**. proxy_score 단독 컷으로는 못 거름

### H2: etf_mentions 임계값이 낮다
- etf_mentions=2인 블로그 49건 중 절반 정도가 노이즈, 나머지는 정상 ("삼성전자 주식 알아야 할 내용" 등)
- 임계값을 ≥ 3으로 올리면 정상 짧은 글까지 빠짐

### H3: Vector 검색 시 점수 컷오프가 없다
- 노이즈 블로그의 검색 점수는 모두 **0.4 이하** (0.265, 0.291, 0.320 등)
- 정상 결과는 모두 0.4 초과 (실제 클러스터 query에서 0.5~0.75)
- **이 컷오프 하나만 추가해도 거의 모든 케이스 해결**

## Decision

`vector_store.search()`에 `min_score: float = 0.4` 파라미터 추가, 그 미만은 결과에서 제외.

```python
def search(
    self,
    query: str,
    collection: str,
    top_k: int = 5,
    min_score: float = 0.4,  # 노이즈 컷오프
) -> list[dict]:
    ...
    for fid, score in zip(faiss_ids, sim_scores):
        if score < min_score:
            continue
        ...
```

## Rationale

### 왜 0.4인가
실제 클러스터 query 4종으로 검증:

| Cluster query | 블로그 top-1 score | 뉴스 top-1 score |
|---|---|---|
| 레버리지/매수/사람 | 0.686 | 0.672 |
| 비트코인/코인/달러 | 0.677 | 0.671 |
| 유가/반도체/AI | 0.588 | 0.446 |
| 펀드/자녀/계좌 | 0.734 | 0.759 |

→ 정상 결과는 모두 0.44 이상. 노이즈는 모두 0.36 이하. **0.4가 자연스러운 분리점**.

### 왜 더 보수적인 0.5나 0.35가 아닌가
- 0.5: "유가/반도체/AI" 클러스터의 뉴스 top-1(0.446)이 빠져버림 — 정상 결과 손실
- 0.35: 노이즈 일부(0.359)가 통과
- 0.4: 자연스러운 valley에서 분리

### 왜 H1·H2 대신 H3만 채택했는가 (점진적 개선)
- H1·H2(필터 강화)는 인덱스 자체를 바꿔야 함 → 변경 영향 큼, 정상 데이터 손실 위험
- H3(검색 컷)는 검색 시점에만 적용 → 인덱스 안 건드림, 롤백 = `min_score=0.0` 한 글자
- **저위험·고효과부터 적용하고 1주 운영 후 H1·H2 추가 결정**

### 핵심 원칙
> **"문제는 한 번에 한 변수만 바꿔서 해결한다."**
> 동시에 여러 곳을 고치면 효과 측정도 롤백도 어렵다.

## Consequences

**Positive**:
- 검증된 노이즈 케이스 전부 제거 (0.265~0.359 점수의 등산일기·언박싱·운세 등)
- 정상 클러스터 query 결과 그대로 유지
- 코드 변경 최소 (vector_store.py 5줄), 호출부 5곳 자동 적용

**Negative**:
- 단어 1~2개짜리 짧은 query는 점수가 낮아져 결과 0건 가능 (실제 RAG에선 클러스터명 + 키워드 5개 조합이라 무관)
- 임계값이 모델·데이터에 의존 → 임베딩 모델 교체 시 재조정 필요

**Neutral**:
- 1주 운영 후 옵션 B (etf_mentions ≥ 3 인덱싱 필터) 추가 도입 결정

## Validation

배포 후 동일 query 재실행 결과:

| Query | Before (top-1) | After (top-1) |
|---|---|---|
| "레버리지" | 아침뉴스 (0.320) | (컷오프 통과 없음) ✓ |
| 레버리지 클러스터 | (혼재) | 커버드콜 ETF 월배당 KODEX 예시 (0.686) ✓ |
| "샥즈 언박싱" 노이즈 | top에 등장 | 모든 query에서 사라짐 ✓ |
